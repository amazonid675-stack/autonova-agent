# Tools

The current tool registry covers public research, GitHub, code-execution proposals, document reading, image generation, HTTP requests, scoped storage, browser handoff, camera, voice, screenshots, and notifications. Each registered server tool declares a version, purpose, input/output contract, network requirement, bounded timeout, retry behavior, and audit policy. Tool policy is user-controlled through ASK, ALLOW, and DENY records, and consequential Android actions use explicit confirmation.

Before a network-capable tool can transmit content, Autonova shows the route and the relevant scope: browser handoff opens visibly; research accepts only owner-selected public HTTPS sources; a GitHub operation is stored as a pending, inspectable record; a scoped workspace file write names its source file, repository path, branch, and commit message before final confirmation; and cloud fallback presents the original prompt for approval. `DENY` blocks tool selection, while `ASK` moves the task into a visible approval state. Sensitive values are redacted from activity, evidence, and operation summaries.

The registry is not a general dynamic plugin runtime and does not grant arbitrary shell, device-root, silent browsing, or blanket network access. New tools must define a narrow purpose, input/output contract, permissions, network requirement, audit event, timeout, failure behavior, and test coverage before they are presented as available.
